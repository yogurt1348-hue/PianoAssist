# Задание Claude для PianoAssist

Продолжи существующий проект PianoAssist на C++/JUCE. UI уже утверждён, работа над предупреждениями Windows уже идёт. Не начинай новый дизайн и не пересоздавай проект. Сначала прочитай инструкции репозитория, текущий CI и существующую упаковку: по предыдущему отчёту установщик уже существовал. Доработай его, если он есть, вместо создания параллельного механизма.

## Результат этой итерации

Нужны две Windows x64 Release-поставки одной версии и одного коммита:

- `PianoAssist-<version>-windows-x64-setup.exe` — установка и обновление поверх предыдущей версии.
- `PianoAssist-<version>-windows-x64-portable.zip` — распаковать в папку и запускать без установки.

Дополнительно: сохранение настроек каждой композиции в отдельную папку, подключение новой иконки, проверка упаковки и документированный порядок ручной проверки на Casio. Отсутствие других тестировщиков не блокирует работу: автоматизируй доступные проверки, реальные музыкальные проверки выполнит владелец приложения.

## Установщик и обновление

Используй существующий инструмент упаковки; если его нет, выбери Inno Setup. Обычная установка для текущего пользователя без обязательных прав администратора, стабильный идентификатор приложения, записи удаления, ярлыки меню Пуск и опционально рабочего стола. Укажи корректные название, издателя, версию и иконку.

Повторный запуск установщика новой версии должен обновлять существующую установку, не создавать дубликаты и не удалять настройки, композиции, состояния плагинов и пользовательские звуки. Перед заменой файлов попроси закрыть приложение; не завершай его принудительно с потерей состояния. Обрабатывай отказ, занятые файлы и незавершённую установку. Пользовательские данные не храни в папке установленной программы.

Сделай в приложении «Проверить обновления»: проверка GitHub Releases, показ установленной и доступной версии, описания и ссылки на подходящий установщик. Проверка не должна блокировать UI, требовать входа в GitHub или мешать офлайн-работе. Обычная версия предлагает только стабильные релизы; тестовые — отдельная настройка. Обрабатывай ошибку сети и ограничение API. Без согласия пользователя ничего не устанавливай и не перезапускай. На этом этапе достаточно открыть страницу релиза и затем выполнить обновление скачанным установщиком; полностью автоматический загрузчик и фоновое обновление не нужны.

Если текущая сборка использует test-build теги, явно определи политику сравнения версий; не сравнивай строки лексикографически и не полагайся на порядок названий тегов.

Не обещай исчезновение предупреждений Windows. Сохрани текущую работу по подписи, проверке и диагностике. Не отключай защиту и не добавляй исключения. Секреты подписи не добавляй в репозиторий.

## Portable

В ZIP должны быть все необходимые распространяемые зависимости, лицензии и краткая инструкция. Не требуй установленной среды разработки или FL Studio. VST3, SoundFont и сторонние библиотеки пользователя не включай.

Явный portable-маркер рядом с exe включает хранение настроек в `Data/` рядом с приложением. Проверь возможность записи; при недоступной папке предложи выбрать другую, не переключайся незаметно на установленный профиль. При обновлении portable пользователь закрывает приложение и заменяет программные файлы, сохраняя `Data/`; подробно опиши это. Не требуй удаления старой папки целиком. Перенос всей папки на другой диск должен сохранять внутренние относительные ссылки. Внешние библиотеки и плагины могут потребовать повторного выбора.

## Папки композиций

Нужна локальная библиотека, без сервера. Для установленной версии корень по умолчанию — подпапка `Songs/` пользовательского каталога данных PianoAssist; для portable — `Data/Songs/`. Дай выбор корня библиотеки и команду «Открыть папку композиции».

Каждая композиция — папка со стабильным уникальным ID, JSON-манифестом версии схемы, копией исходного MIDI при импорте, файлами состояния плагинов и при необходимости превью. Оригинальный MIDI пользователя никогда не изменяй. Читаемое название папки дополняй ID, исключи коллизии и недопустимые символы Windows. Пользователь должен понимать, что импорт создаёт копию.

Сохраняй: имя, исходную информацию, хеш MIDI, назначение рук/ролей, приглушение и громкость дорожек, MIDI-каналы и инструменты, SoundFont-ссылки, идентификаторы VST3 и их состояния, режим рук, ожидание нот, воспроизведение другой руки и backing, темп, допуски, границы цикла, позицию и масштаб отображения. Сохраняемая позиция не означает автоматический старт воспроизведения после открытия.

Глобально сохраняй MIDI/аудиоустройства, общую задержку/калибровку, тему, масштаб UI, язык и папки сканирования плагинов. Не привязывай устройства конкретного компьютера к каждой композиции без явной необходимости.

Используй debounce и атомарную запись, версии схемы и миграции, ограниченную резервную копию. Повреждённое состояние не должно уничтожать MIDI или мешать открыть композицию с настройками по умолчанию. Большие binary-state плагинов сохраняй отдельно от JSON и вне аудиопотока. Отсутствующий плагин/SoundFont обозначай с возможностью повторно указать файл; сохраняй исходное назначение до явной замены пользователем. Файлы звуков и плагины не копируй в библиотеку автоматически.

## Иконка

Прилагается новая иконка PianoAssist, вдохновлённая монограммой Fe-Anor. Название приложения остаётся PianoAssist. Добавь исходный PNG в assets и подготовь Windows ICO со слоями 16, 24, 32, 48, 64, 128 и 256 px. При необходимости упрощённые маленькие размеры делай явно отдельными ресурсами. Проверь читаемость на тёмном и светлом фоне.

Подключи иконку к exe/ресурсам JUCE, окну приложения, установщику, удалению и ярлыкам. Проверь, что релиз не использует стандартную иконку JUCE. Дай инструкцию по перепривязке ярлыка, если Windows показывает старую закэшированную иконку.

## Проверки и приёмка

- CI собирает обе поставки из одного коммита и публикует их вместе с SHA-256, версией и commit SHA. Не называй текущую непроверенную сборку стабильной автоматически.
- Чистая установка без среды разработки; запуск без MIDI-устройства; подключение позднее; удаление с сохранением данных по умолчанию.
- Обновление N → N+1 сохраняет библиотеку, глобальные настройки и состояния VST3, не дублирует установку.
- Portable запускается после распаковки и переноса папки; обновление сохраняет Data.
- Повторное открытие композиции восстанавливает настройки и цикл. Две разные композиции и файлы с одинаковым именем не делят состояние.
- Проверь недоступный каталог, повреждённый JSON, пропавший VST3/SoundFont, отсутствующую сеть и ситуацию «обновлений нет».
- Установленная и portable версии не смешивают данные без явного импорта.
- Реальное поведение нот, педали, аккордов и задержки пометь как ожидающее проверки владельцем, если физической проверки не было.

Работай небольшими итерациями, проверяй существующие функции после затронутых изменений. В конце предоставь ссылки на две реальные поставки, список проверок с результатами, ограничения, путь к данным, инструкцию обновления и короткий чек-лист владельцу. Если публикация или merge требуют отдельного разрешения по правилам проекта, подготовь результаты и сообщи конкретный оставшийся шаг. Не заявляй, что поведение проверено, если проверялась только сборка.
