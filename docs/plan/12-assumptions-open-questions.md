# Assumptions and open questions

## Decisions made for MVP

| Topic | Decision | Why |
| --- | --- | --- |
| Platform | Windows 10/11 x64, one local user | Matches request and narrows device/installer scope |
| Framework | C++ with JUCE and CMake | Requested stack; portable core remains possible |
| Piano input | One generic USB MIDI input at a time | CDP-S110 should be class compliant; avoids vendor SDK dependency |
| MIDI source | Local SMF format 0/1 | Covers common piano arrangements with bounded parser scope |
| Visuals | Piano roll, not engraved score | Robust MVP visualisation with clear timing |
| Scoring | Pitch/onset only, strict gate | Defines predictable initial lesson behaviour |
| Tolerance | 120 ms early / 180 ms late default | A playable default; user-configurable later |
| Sustain | Read/visualize, not scored | Avoids ambiguous pedal pedagogy in first release |
| Accompaniment | Source-MIDI backing playback | Meets need without speculative automatic-arranger design |
| Instrument | Internal synth first | Keeps MVP locally runnable; VST3 is later |
| Stop behaviour | Cancel future scheduling, release voices; tails may remain | Correct MIDI/audio semantics |

## Open questions for product owner

1. Should a gate pass immediately when the chord is complete, or wait until the nominal onset/time window ends for rhythmic feedback? MVP assumes immediate pass.
2. Should the user be allowed to adjust strictness from a simple three-level control, or expose milliseconds? MVP stores milliseconds but can present levels.
3. Does `auto-accompaniment` eventually mean generated accompaniment from chords/styles, rather than playback of existing backing tracks? The MVP deliberately interprets it as existing-track accompaniment.
4. Which notation expectation matters after MVP: staff notation, finger numbers, or both?
5. Is audible metronome/count-in required for first user tests?
6. Which VST3 license/distribution and crash-isolation expectations apply to public release?

## Risks to revisit

Hand inference cannot reliably solve every arrangement. Audio/MIDI latency varies by driver. Some MIDI files contain unusual note pairing or tempo data. Future plug-ins can add latency, tails, instability, and licensing obligations. Keep these risks visible in diagnostics and tests instead of hiding them behind optimistic defaults.
