# Где PianoAssist хранит данные и как обновляться

## Две сборки одного коммита

| Сборка | Файл в релизе | Данные |
| --- | --- | --- |
| Установщик | `PianoAssist-<версия>-windows-x64-setup.exe` | `%APPDATA%\PianoAssist` |
| Портативная | `PianoAssist-<версия>-windows-x64-portable.zip` | папка `Data` рядом с `PianoAssist.exe` |

Портативный режим включает файл `PianoAssist.portable` рядом с exe. Если в `Data` записать нельзя, PianoAssist попросит выбрать папку на этот запуск и молча в профиль не переключается. Установщик удаляет этот маркер из своей папки, поэтому установленная версия всегда пишет в `%APPDATA%`.

В папке данных:

| Что | Где |
| --- | --- |
| Настройки | `settings.json` |
| Журналы | `logs\pianoassist.log` (5 МиБ × 5 архивов) |
| Библиотека композиций | `Songs\` (можно сменить: Настройки → Практика → папка библиотеки) |
| Список найденных VST3 | `plugins.xml` |
| Настройки главного VST3-инструмента | `instrument-<hash>.state` (по файлу на плагин) |

## Библиотека композиций

- При открытии MIDI-файла в библиотеку кладётся **копия**. Исходный файл только читается и никогда не изменяется.
- Каждая композиция — папка `Название [id]`: `song.mid`, `manifest.json` (дорожки, руки, звуки, громкости, темп, диапазон A–B, позиция, зум, время последнего открытия) и `plugin-state\` с состояниями VST3 для её дорожек.
- Одинаковые названия не конфликтуют: папки различаются по id. Тот же файл повторно не копируется (сравнение по SHA-256).
- **Файл → Библиотека композиций… (Ctrl+B)**: список, недавние сверху. Можно открыть композицию с её настройками, открыть её папку или убрать из библиотеки.
- «Убрать из библиотеки» спрашивает подтверждение и удаляет только папку композиции внутри библиотеки. Исходный MIDI не удаляется. Если композиция открыта, она сначала закрывается.
- Если копия `song.mid` пропала, строка помечается красным, и открыть её нельзя. Откройте исходный файл снова: он будет импортирован заново.
- Повреждённый `manifest.json` сохраняется как `manifest.json.bad`, используются настройки по умолчанию.

## Обновление

**Установщик.** Запустите новый `setup.exe` поверх установленного. Он закроет PianoAssist, если тот открыт, заменит программу и не тронет `%APPDATA%\PianoAssist`. Сам приложение не перезапускает.

**Портативная.** Закройте программу. Скопируйте новые `PianoAssist.exe` и `licenses` поверх старых, папку `Data` не трогайте. Подробно — в `README.txt` внутри архива.

**Проверка обновлений.** Помощь → «Проверить обновления» спрашивает GitHub о релизах этого репозитория. Она ничего не скачивает и не устанавливает, только показывает версию и открывает страницу релиза (только `https://github.com/…`). Тестовые сборки предлагаются, если в Настройках включено «Включать тестовые сборки».

## Версии

- Стабильный релиз — тег `vX.Y.Z`. Тестовая сборка — пре-релиз `test-build-N` (`N` — номер запуска CI); версия программы берётся из имени файла `PianoAssist-0.2.0-windows-x64-setup.exe`.
- Сравнение числовое: сначала версия, потом номер тестовой сборки. Тестовая сборка 0.2.0 считается более ранней, чем стабильная 0.2.0.
- Версия и коммит видны в «О программе» и в журнале.
